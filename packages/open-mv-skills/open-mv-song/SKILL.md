# 歌曲解析与分镜脚本

## 何时使用

- 手上是一首歌（有 WAV 文件，或已知 BPM / 段落），要把它变成 MV。
- 需要先知道「哪里是副歌、能量怎么走」，再决定画面。

整体气质与调色 → `open-mv-director`；歌词行细节 → `open-mv-lyric`；卡点密度 → `open-mv-beat`。

## 与短片流程的区别

短片是「剧本 → 脚本 → 音乐」；MV 是「歌曲 → 音乐结构 → 与歌曲匹配的脚本 → 画面」。
不要拿短片的分镜习惯先写剧本再配歌——音乐已经存在，画面必须服从它。

## 工作流

1. **解析。** `open-mv analyze song.wav`（或 `analyzeWav(path)`）得到 BPM、拍偏移、
   时长、段落（intro/verse/chorus/outro）与能量。
2. **核对。** 用听感检查三件事：BPM 是否与实际节拍一致（允许 ±1 的估计误差）、
   副歌起点是否落在听到的段落切换处、尾奏是否被吃掉。段落是**辅助判断**，不是事实。
3. **写脚本。** `planSongMv({ song, lines, palette, ... })` 生成 `SongMvPlan`；
   不要直接手搓场景，脚本层负责段落→镜头、运镜、字效与歌词分配。
4. **审阅脚本。** 把 plan 打成 JSON 逐镜头看：段落的起止、运镜、每行歌词落在哪个镜头。
   修正方式是改数据（`SongProfile.sections` 或 `lines`），不是改渲染代码。
5. **编译与渲染。** `compileSongMv(plan)` → `open-mv render films/<x>.ts -o out.mp4`。
6. **验收。** 抽帧看每个段落至少一帧；`ffmpeg -af volumedetect` 看峰值不过 0 dBFS；
   确认副歌的重音与画面变化同帧。

## 修正优先级

1. 段落边界错 → 手写 `sections` 覆盖（这是脚本层数据，允许改）。
2. BPM 明显错（差 > 3）→ 手动填 `bpm`，不要改画面去迁就错误节拍。
3. 歌词行数量与段落不匹配 → 调整 `lines` 数量或给某行指定字效，不要缩字号硬塞。

## 硬约束

- 解析只接受 PCM WAV；其他格式先转换，不做隐式解码。
- 解析不给调性/和弦/音色结论；不要据此宣称「音乐分析完成」。
- 不要跳过脚本直接出片后再回头解释；脚本是 MV 流程的可审阅产物。
- 分析失败或文件缺失要显式报告，不要用假 BPM 继续出片。
