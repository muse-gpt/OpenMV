# MV 导演工作流

## 受众

独立音乐人、MV 导演、需要给单曲配影像的创作者，以及代 agent 执行 MV 项目的助手。

## 何时使用

- 已有一首歌（或 BPM、段落结构）与歌词，需要把它变成画面。
- 需要决定「整片是什么气质」，而不是只写一段文字动画。

## 先分清流程

短片是「剧本 → 脚本 → 音乐」；MV 是「**歌曲 → 音乐结构 → 与歌曲匹配的脚本 →
画面**」。不要按短片习惯先写剧本再配歌：音乐已经存在，画面服从音乐。

歌曲解析与脚本生成 → `open-mv-song`；
单行歌词的字效与 timing → `open-mv-lyric`；卡点与鼓组落点 → `open-mv-beat`。

## 先确认事实

1. 拿到歌曲文件（或 BPM、拍号、段落）与歌词；有文件就先 `open-mv analyze`。
2. 确认是否有可用的音频文件或合成歌声；没有就先声明只有 BGM 与音效。
3. 确认画幅与帧率（横屏 1920×1080 / 竖屏 1080×1920 / 其他），帧率决定卡点精度。

## 工作流

1. **解析歌曲。** `analyzeWav` 得到 BPM、拍偏移与段落能量，按听感核对副歌起点。
2. **画能量曲线。** 在解析结果上标出能量高低：副歌是峰、主歌是平台、尾奏回收。不要每小节都堆同样的元素。
3. **选调色板。** 从预设 catalogue 选一个（见 [presets.md](references/presets.md)），整片只用一个，靠运镜与元素变化制造层次。
4. **写分镜脚本。** `planSongMv` 把段落翻成镜头，运镜按段落能量自动选；审阅后再改。
5. **排歌词。** 一行一拍组（默认 4 拍），字数多的行拆行，不要靠缩字号硬塞。交给 `open-mv-lyric` 处理。
6. **卡点。** 段落头落 impact、拍点落 tick、副歌前落 riser；密度宁少勿多。交给 `open-mv-beat`。
7. **编译与验收。** `compileSongMv` + `open-mv render` 出片；逐段检查文字可读性、能量是否与音乐同步、有没有空白段落。

## 硬约束

- 引擎当前没有转场与多轨合成：场景之间是硬切，元素按列表顺序绘制。不要承诺淡入淡出以外的转场效果。
- 合成歌声合同是 5 个元音 × 7 个起音类，不能直接唱任意歌词；需要真实人声时用导入音频，并声明这是外部素材。
- 参考片名/歌手不能直接当风格参数；拆成色彩、构图、运动、光线、剪辑倾向，并与创作者确认。
- 段落与 BPM 来自解析时是估计值；不要把它们说成人工标注的事实。
- 不把预览或截断渲染说成成片；失败如实报告。
